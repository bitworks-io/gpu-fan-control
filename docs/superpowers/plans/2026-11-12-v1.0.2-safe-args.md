# v1.0.2: safe command-line handling (implementation plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development for each task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** an uninstall can never hang or leave a fan under app control when v1.0.2 is the installed exe after any 1.1 build was installed earlier ("1.1 → 1.0.x downgrade").

**Architecture:**
- A pure decision in Core (`LaunchDecision`, unit-tested) picks Tray, Stop or Unsupported before anything else runs.
- `--stop` is the real graceful stop, backported from 1.1 (`StopSignal`, `StopCommand`, `StopOutcome`, `SingleInstance.TryAcquire/Release`).
- Every other `--*` argument exits 3 at once: no mutex, no tray, no modal.
- A launch with no arguments behaves exactly like v1.0.1, plus the stop listener in the tray.

**Tech stack:** C# (app net48 WinForms; Core netstandard2.0; tests net8.0 xunit).

**Spec:** the uninstall-downgrade fix plan on the 1.1 branch (`docs/superpowers/plans/2026-11-09-uninstall-downgrade-residual.md`, option D and its §7 review conditions).

## Why

- Inno Setup appends uninstall logs across over-installs, and the uninstaller and its `[Code]` come from the LAST installer.
- After a 1.1 build and then a 1.0.x over-install, the recorded 1.1 `[UninstallRun]` entries (`--stop`, then `taskkill`, then `--restore-auto`) run against the 1.0.x exe.
- v1.0.1's `Main()` takes no arguments, so `--stop` starts a tray. On a machine with no supported GPU it shows a modal, and `waituntilterminated` blocks the uninstall forever. A CI repro reproduces this deterministically.
- With v1.0.2 the same entries run safely:
  1. `--stop` gracefully stops a running 1.0.2 tray (its normal exit restores the fans);
  2. `taskkill` finds nothing;
  3. `--restore-auto` exits 3.

## Global constraints

- **No-argument launch:** identical to v1.0.1, except that the tray also listens for the stop event. The mutex name, its creation (`new Mutex(true, "Local\\LightweightAmdGpuFanControl.SingleInstance", out bool createdNew)`), the "already running" MessageBox text, and `Application.Run(new SystrayApplicationContext())` stay exactly as in v1.0.1.
- **Event and mutex names** equal 1.1's: `Local\\LightweightAmdGpuFanControl.Stop` and `Local\\LightweightAmdGpuFanControl.SingleInstance`. That way a 1.1 `--stop` reaches a 1.0.2 tray, and a 1.0.2 `--stop` reaches a 1.1 tray.
- **`--stop` never creates the stop event and never ends a process.** Exit codes: 0 stopped; 3 not running; 1 timeout, a running instance without a listener (v1.0.0/v1.0.1), or an error.
- **No installer change.** `installer/*.iss` changes ONLY its default `MyAppVersion`.
- **Version 1.0.2** in `VERSION`, the app csproj `<Version>`, and the iss default `MyAppVersion`.
- **Public repo:** no machine names, serials, internal hostnames or private ids in code, comments, docs or commits.

## Review focus (inputs no task should break)

1. `--stop` while nothing runs → 3, with no tray and no modal (the uninstall case on a machine with the app not running).
2. `--stop` while a v1.0.1 tray runs (no listener) → 1, with that tray left untouched.
3. `--restore-auto`, `--probe`, `--reset-tuning-to-factory --gpu 768`, and any unknown `--x` → 3 immediately, with no mutex taken (a running tray is never shown an "already running" modal by a second process).
4. Arguments that don't start with `--` (`/stop`, `foo`) → the tray, as v1.0.1 (v1.0.1 ignored all arguments).
5. Mixed `--stop --x` → 3 (only exactly one `--stop` argument means stop).

### Task 1: Core decision and exit codes

**Files:**

- Tests: `LightweightAmdGpuFanControl.Tests/LaunchDecisionTests.cs`, `StopOutcomeTests.cs`.

**Interfaces (produced):**
- `namespace LightweightAmdGpuFanControl.Cli; public static class ExitCodes { public const int Ok = 0; public const int Error = 1; public const int NothingToDo = 3; }`. These values equal 1.1's.
- `public static class StopOutcome { public static int ExitCode(bool instanceRunning, bool eventExisted, bool exitedInTime) }` is copied verbatim from 1.1.
- `public enum LaunchAction { Tray, Stop, Unsupported }`
- `public static class LaunchDecision { public static LaunchAction Decide(IReadOnlyList<string>? args) }`, with these rules, in order:
  1. null or empty → `Tray`;
  2. no element starts with `--` (`StringComparison.Ordinal`) → `Tray`;
  3. exactly one element, equal to `--stop` (`StringComparison.OrdinalIgnoreCase`, as 1.1) → `Stop`;
  4. otherwise → `Unsupported`.
